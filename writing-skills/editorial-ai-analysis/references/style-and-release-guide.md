# 用户文章风格与发布前自检

## 适用产物

面向公众号、网页或公开读者的中文科技分析文章。常见议题：AI、Agent、开源、软件工程、芯片与模型生态、创新组织。

目标不是新闻复述，也不是企业宣传稿。文章应当从一段真实材料或事件出发，解释一个正在变化的机制，并给出审慎、可讨论的判断。

## 已确认的视觉语言

- 用白底、近黑正文、深红色作为主色，辅以克制的暖金或浅灰；整体干净、安静、编辑感强。避免霓虹赛博、重金属朋克、过分文艺或大面积渐变。
- 首屏由文章标题、副标题、短导语和一幅“表达论点”的图组成。标题直接、有判断，例如“Pencils Down之后：代码不再是默认语言”。副标题说明研究对象与问题。
- 图优先采用内嵌 SVG 或极简演示胶片风格。每幅图必须回答一个问题：
  - 机制图：输入、治理、输出如何连接；
  - 取舍图：不同架构、组织或路径在什么约束下成立；
  - 演化图：过去—现在—下一阶段的转变；
  - 判断框架：哪些条件决定结论是否成立。
- 图要能独立被读懂：有简洁标题、清楚节点/坐标、短说明文字和 figcaption。图不用于重复段落内容。
- 不使用泛化的机器人、芯片、霓虹城市或抽象人像作为无信息插图。若确有人的图，必须服务于“人如何处于系统/选择之中”的论点，保持极简，不煽情。
- 文章通常穿插 2–3 张图；图的位置与首次需要解释的论点相邻，而不是集中堆在开头。

推荐的色彩层级（可随主题微调）：

| 用途 | 建议 |
| --- | --- |
| 主强调 | 深红 `#b90000` 或相近色 |
| 正文 | 近黑 `#171717` |
| 背景/卡片 | 暖白 `#fbfaf8`、浅灰 `#f3f1ed` |
| 次强调 | 暖金 `#b88a36`，只用于关系线、关键节点或提示 |

## 文章结构与语言

1. **开头 2–4 段**：从原始人物的话、一个技术转折或一段具体场景进入。立即说明“为什么这件事值得讨论”，不要铺陈背景。
2. **拆开源材料**：还原其原意、上下文与可验证事实。引用不超过必要长度，重点是解释。
3. **给出机制判断**：说明变量为什么变了、旧经验哪里仍有效、哪些边界不可跨越。
4. **落到实践**：企业、项目、社区或开发者应调整什么。建议应具体到工作机制、评价口径、组织安排或技术治理，不写空泛口号。
5. **收束**：用一句有力量但不过度修辞的话回扣主旨；开放讨论而不代替读者下结论。

结构按议题决定，避免为了整齐机械地套“每章三点”“每节十条”。三个故事可合并为“观察与小故事”，不必各自成章。每一段都要增加新的事实、推理或选择；能删去的重复，直接删。

语言应平实、有张力、略带文学感但不散文化。少用“震撼”“开炮”“颠覆”“终局”“必须”“唯一”“空洞”等强断言。不要把内部评语、删改理由、写作过程留在正文。战略与愿景可以正面讨论，但要与社区文化、工程机制、业务和生态互补，而不是制造对立。

中文表达优先。保留必要的英文术语、项目名和原话，并在首次出现时用一句自然中文解释。结论应清楚区分：

- **原始材料称/演讲者认为**：只能说明来源的主张；
- **公开资料显示/可交叉核验**：可作为事实基础；
- **本文的判断是/可以推导为**：明确是分析者的推论。

## 研究与引用

- 新近事件优先找官方原文、官方视频/逐字稿、项目仓库、论文或正式公告。媒体报道和社区逐字稿用于补充与交叉核验，不能替代一手材料。
- 对性能、融资、用户规模、产品时间线、事故或竞争对手相关主张，保留来源与时间。无法验证时不要虚构确定性；可用“据演讲表述”“尚无独立基准”等准确限定。
- 文末提供“资料与注释”或“参考来源”，链接到可访问的具体页面，不链接搜索页。
- 不要把用户提供的评价直接当作事实。先核验，再将可保留的部分写成有边界的判断。

## 公共发布自检

在交付前以外部读者审稿：社区开发者、普通大众、政府与行业主管部门、企业管理层与开源负责人。

- **准确性**：日期、组织、引用、技术定义、指标是否准确？性能和计划是否被误写成已经验证的结果？
- **可识别性**：个人故事是否由多项细节拼接而可反向识别？若可能，写成足以说明机制的匿名观察。
- **表达与合规**：避免无证据归责、对企业/个人的动机揣测、对外部组织的贬损或对抗性标签。避免将组织管理问题写成对某一企业资源配置的影射。
- **产业关系**：讨论中国或国际化时，避免二元对立和泛化判断。强调开放协作、技术创新、合规治理、生态互利与可持续性。
- **安全**：不要给出可被直接滥用的攻击、绕过、渗透或不当自动化操作细节。提及 Agent 治理时，应包含权限、审计、人类监督、数据最小化和合规边界。
- **读者价值**：读者能看出它与工程、产品、商业或生态的关系，而不是认为文章脱离实践、无病呻吟或只在造概念吗？

## 当前可参考的成品

- `pencils-down-v1.html`：红白编辑风、机制图、对演讲主张与独立事实的边界处理。
- “AI 时代创新组织复合体”文章：用图表解释组织机制，而非仅插图。
- “Claude Code 消失之后”与“Agent没有终结编程”文章：技术叙事、结构化判断与适度国际化推演。

这些是风格参照，不是内容模板。后续若用户反馈新的偏好，应更新本指南，覆盖已失效的习惯。
