# 当计算机重新属于我们

## Omarchy、可塑机器与 Agent 时代的一场开源实验

> 开源曾经给人修改软件的权利。Agent 正在降低行使这种权利的成本。二者相遇，可能改变的不只是一款 Linux 发行版，而是人与计算机之间的关系。

公开讨论稿 v1｜2026 年 9 月

**导语｜** 9 月中旬，一个看上去并不缺话题的 Linux 项目又一次进入技术媒体的视野。据 Omacom Foundation 截至 2026 年 9 月公开的信息，围绕 Omarchy 的个人捐赠、企业多年期承诺和模型 Token 额度等合计约 1850 万美元。支持者不断增加，质疑也随之升温。有人把它看作 Agent 时代的个人计算入口，也有人说它不过是 Arch Linux、窗口管理器和一套个人配置的重新包装。

几乎同时，Frank Da Silva 发表长文《The Malleable Machine》，写下自己为何被这个项目吸引。文章并未把重点放在某项单一性能指标上，而是反复回到一句更直接的话：**Own the machine——拥有这台机器。**

这句话听起来像早期个人计算机文化的回声。但在 Agent 开始获得终端、文件、应用和系统操作能力之后，它又有了新的含义：我们买下了一台计算机，是否也真正拥有改变它、理解它以及离开某个供应商的能力？

这才是 Omarchy 值得观察的地方。

## 一、1850 万美元，首先不是一轮普通融资

先把事实说清楚。

Omarchy 是 DHH 发起的、基于 Arch Linux 的开放源代码桌面系统。它从一套高度个人化的 Arch 与 Hyprland 配置起步，后来逐步加入安装器、桌面组件、软件包、插件体系和面向 Agent 的系统入口。

截至 2026 年 9 月，Omacom Foundation 公布的捐赠与承诺约为 1850 万美元。这个数字由个人捐赠、企业多年期承诺、开放捐赠以及模型厂商提供的 Token 额度等共同组成，不能简单理解为一家创业公司完成了 1850 万美元股权融资，更不能等同于已经到账、可以自由支配的现金。

但它仍然重要。

一批科技企业家、云服务商、密码管理厂商和模型公司，愿意把现金、算力或模型额度投向一个诞生不久的桌面 Linux 项目，说明他们押注的并不只是另一个发行版。他们看到的可能是一个新的入口：当 Agent 从聊天窗口走向操作系统，谁能为它提供可读、可改、可执行又足够完整的环境，谁就有机会重塑个人计算的界面。

基金会公布的资金用途也颇有意味。它不仅要维护 Omarchy 本身，还要资助所依赖的上游项目、聘用内核和桌面组件开发者、支持艺术家、提供基础设施并组织插件生态。换句话说，它试图把个人影响力带来的注意力，转化为一套可持续的开放源代码生产关系。

这一步能否成功，还需要时间检验。但资本和资源的快速汇聚至少说明：在模型之外，Agent 需要怎样的运行环境，已经成为新的产业问题。

## 二、《可塑机器》真正触碰了什么

Frank Da Silva 的长文并不是一篇技术评测。它更像一名长期使用者对个人计算的重新追问。

文章从 DHH 与 Lex Fridman 的长谈写起。DHH 描述了自己如何把越来越多实现工作交给编码 Agent：Agent 可以检查文件、运行测试、查询文档、修改代码、观察失败并继续尝试。人的工作随之上移到架构、产品判断、测试、选择与审美。

Da Silva 由此抓住了一个关键区别：**开源提供的是许可，Agent 提供的可能是能力。**

一段源代码即使公开摆在互联网上，对绝大多数人而言仍然难以修改。理解项目结构、搭建开发环境、追踪问题、编写补丁并验证兼容性，每一步都有门槛。开放许可证回答了“允许不允许”，却没有自动解决“会不会”和“改不改得动”。

Agent 正在缩短这段距离。面对一个由文本配置、脚本、命令行工具和开放代码构成的系统，Agent 可以读取配置、解释日志、查询服务、比较差异、提出修改并运行验证。用户依然要对结果负责，但如今更多使用者可以用自然语言调动一部分过去需要专业训练才能调用的系统能力。

因此，“可塑”并不只是可以更换主题或快捷键。它意味着计算机不再只是一件由厂商定义完成、用户被动接受的成品，而有机会重新成为一种可以持续改造的媒介。

这并非完全崭新的理想。个人计算的早期先驱就曾把计算机设想为人人可以拥有、可以表达和创造的动态媒介；过去十余年，Malleable Systems Collective 等社区也一直主张，软件应当像使用起来一样容易修改。Agent 带来的变化，是让这一长期理想获得了更现实、也更可能规模化的实现工具。

## 三、真正巧妙的不是“无限选择”，而是“先给答案，再允许改写”

传统桌面 Linux 的自由，常常以选择成本的形式出现。

用户可以选择发行版、桌面环境、窗口管理器、软件源、终端、状态栏和数十种配置方式。对熟悉 Linux 的人，这是一片乐园；对普通用户，它也可能是一张没有起点的地图。许多人不是不想掌控计算机，而是没有时间先成为系统集成工程师。

Omarchy 的答案不是取消主见，而是把主见做成产品。它用 **omakase**——“由主厨搭配”——解释自己的设计：先交付一套风格鲜明、内部协调、可以直接工作的默认方案，再为使用者保留较大的检查、调整和替换空间。

这构成了一个看似矛盾、实际很重要的组合：

- **有主见的默认值**降低第一次使用的成本；
- **开放、文本化的系统**保留深入修改的可能；
- **Agent**把相当一部分修改从“先学会编程”变成“描述目标、审阅变化并验证结果”。

好的默认值与用户主权并不冲突。餐厅可以先端出一套完整菜单，但厨房不能因此把门焊死。对于 Agent 时代的操作系统，产品化的关键或许正是这句话：先让我立刻开始，再让我随时接管。

这也解释了为什么 Omarchy 的审美并非无关紧要。统一的视觉、明确的交互和带有个性的语言，让抽象的“可塑计算”变得可感知。技术项目因此不再只是软件包的集合，而开始形成身份、故事与共同体。

## 四、它为何开始像一场思想运动

一场技术运动通常需要四种东西：一个真实的不满，一件可以使用的产品，一套容易复述的语言，以及一群愿意共同投入的人。

Omarchy 恰好把它们聚在了一起。

真实的不满，是在部分使用场景中，今天的“个人计算机”越来越像租来的房子。设备可以属于用户，但系统更新、应用分发、云端账号、订阅关系和平台规则仍由别人掌握。用户可以选择墙纸，却很难移动承重墙；一旦供应商改变价格、接口或准入规则，所谓所有权就会显出边界。

可以使用的产品，是一套能够安装、启动和日常工作的 Linux 桌面。批评者说它只是 Arch 加个人配置，这个批评并非毫无根据，尤其适用于项目早期。但从产品视角看，把大量分散组件筛选、整合、调试并形成稳定体验，本身就是价值。餐厅的价值也不在于发明了每一种食材。

容易复述的语言，是“Beautiful, fun & agentic Linux”“The malleable OS”和“Own the machine”。它们没有解释全部技术，却清楚回答了项目想让人感受到什么。技术会快速迭代，能够持续聚集人的，往往是对问题的共同理解。

共同投入的人，则开始通过代码、插件、主题、捐赠、算力和上游维护进入项目。Omacom Foundation 的出现，使这场运动第一次有机会从创始人的个人作品走向机构化供给。

这四者互相增强：语言带来注意力，产品把注意力变成体验，社区把体验变成改进，资金再把一部分志愿劳动转化为可持续的专业维护。

这正是“思想运动”对产业的实际作用。它不是悬在产品上方的口号，而是一种降低协作成本的基础设施：帮助用户理解为什么尝试，帮助贡献者判断什么值得做，也帮助企业知道自己在支持怎样的未来。

## 五、如果这条路成立，产业会发生哪些变化

### 1. 操作系统竞争将增加一个“可塑性”维度

过去的桌面竞争主要围绕应用数量、硬件兼容、性能、安全和使用体验。Agent 进入系统以后，还要增加新的问题：系统是否容易被 Agent 理解？修改是否可追踪？失败能否回滚？权限能否逐项授予？同一任务能否在不同模型之间迁移？

未来所谓 Agent OS，未必是凭空出现的新操作系统。更可能的形态，是传统内核、开放工具链、声明式配置与 Agent 控制层重新组合。竞争焦点也会从“有没有 AI 助手”，转向“用户能否安全地让 Agent 改造自己的环境”。

### 2. 开源从“公共代码仓库”走向“个人软件供应链”

当实现成本下降，大量软件不再需要服务百万用户才值得存在。一个研究者可以为一个项目做一件小工具，一家小企业可以为自己的流程维护十几个内部应用，一个普通用户也可能只因为按钮位置不合适而生成一个个人分支。

软件不会因此变得没有成本。测试、安全、依赖升级和长期维护仍然存在。但软件生产的最小经济规模会下降，“只为少数人存在的软件”将显著增加。

这会抬高开放组件、标准接口、包管理、身份权限、签名验证和可复现构建的价值。Agent 可以快速写出最后一段代码，但它需要一个可信的开放生态作为原料。

### 3. 上游项目可能获得新的价值回流方式

Omarchy 的基金会没有只把钱留给自己的品牌，而是宣布资助 Hyprland、mise 等依赖项目，并把关键上游开发者纳入长期支持。这种做法值得关注。

Agent 会显著加快下游组合与产品化。如果收益只在面向用户的一层聚集，而底层维护者继续无偿承担安全、兼容和基础设施压力，生态很快会失衡。新的发行版或 Agent 平台若想获得长期信任，就必须建立透明、稳定的上游回馈机制。

### 4. “品味”会成为工程能力的一部分

当代码生成变得充裕，新增功能不再天然等于进步。项目真正稀缺的能力会转向取舍：哪些问题值得解决，哪些补丁不应合入，怎样保持整体一致，何时停止生成。

这也是 DHH 个人影响力目前难以复制的部分。他不只带来流量，还提供了明确的审美和决断。它能在项目早期形成速度；随着项目扩大，这些个人判断能否进一步沉淀为公开的架构原则、贡献规则和继任机制，将成为需要持续观察的问题。

## 六、从 Omarchy 回看中国 AI 开源产业

中国已经在开源大模型、Agent、AI 芯片和机器人领域形成一批有国际影响力的项目。Omarchy 带来的启示，不是要求这些项目模仿一种桌面风格，而是提示我们重新理解“开放”的交付单位：开发者最终需要的不是一个孤立仓库，而是一套能够进入、运行、理解、改造和迁移的系统。

### 1. 开源大模型：从开放权重走向可改造的完整系统

以 DeepSeek、Qwen 等为代表的中国模型项目，已经把开放从模型权重延伸到推理组件、训练与部署工具、编码 Agent 和多模态插件。下一步竞争不仅是谁发布更强的模型，也是谁能让不同地区、不同硬件和不同行业的开发者更快把模型变成自己的能力。

这需要的不只是下载地址，还包括清晰的许可证与模型卡、可复现的部署方案、公开评测、推理优化、工具调用接口、硬件适配以及持续响应的社区。Omarchy 所体现的“先给出可用答案，再允许继续改写”，同样适用于大模型：先让开发者可靠地运行，再让他们能够替换组件、接入数据、调整工作流，并保留迁移到其他模型和平台的出口。

### 2. Agent：从开源框架走向可信的工作环境

DeepSeek Harness、Qwen Code 等项目表明，中国开源正在从“提供模型”继续走向“组织模型完成工作”。但一个 Agent 项目是否真正成熟，不能只看能连接多少模型或工具，还要看插件如何隔离、权限如何授予、记忆归谁所有、过程能否审计、失败能否回滚，以及使用者能否更换模型而不丢失自己的数据和工作方式。

Omarchy 把 Agent 放进操作系统，是一个值得观察的方向；中国 Agent 产业更现实的机会，则可能首先出现在研发、办公、制造、医疗和政企服务等工作环境。开源项目如果能够把模型、工具、权限和行业流程组合成可检验的参考实现，就更容易从演示走向生产，也更容易形成合作伙伴可以共同扩展的生态。

### 3. AI 芯片：开放工具链决定硬件能否进入开发者日常

芯片性能最终要通过编译器、算子库、框架适配、调试工具和文档变成开发者能够调用的能力。CANN 及昇腾相关组件的开源开放，使中国 AI 芯片具备了进一步汇聚开发者和硬件伙伴的基础；真正的生态价值，则取决于这些工具是否容易获取、组合、诊断和贡献。

Agent 可能进一步降低算子开发、模型迁移和性能调优的成本，但前提是接口、文档、错误信息、样例和测试基准既能被人理解，也能被机器可靠读取和验证。对芯片企业而言，开放不只是发布一部分代码，而是持续缩短“模型发布”到“在本地硬件稳定运行”之间的时间，并让优化结果能够回到公共仓库、上游框架和可复现基准中。

### 4. 机器人：需要的是“有边界的可塑性”

机器人把模型和 Agent 的行动带入物理世界。OpenLoong、openEuler Embedded 等开放实践，正在尝试连接硬件、操作系统、仿真、控制和具身智能算法。这里同样需要模块化接口、参考设计和可替换组件，但不能简单追求“任何地方都能随时修改”。

操作系统改错了配置，通常还可以重启或回滚；机器人改错了控制策略，可能影响设备和人员安全。因此，机器人开源更需要经过验证的安全边界、仿真测试、权限分层、硬件急停、版本追踪和责任界面。它所需要的不是无限可塑，而是在确定性安全约束内，让高校、开发者、零部件企业和整机厂能够分别创新、共同验证。

### 5. 共同问题：让开放项目成为生态资产

这四类产业面对的是同一个转换：从“我们开放了什么”，转向“别人能够基于它做成什么”。一套有主见的参考实现可以降低第一次使用成本；开放接口和可迁移设计可以保留参与者的选择；基金会、技术委员会或其他相对中立的治理机制，可以承接跨企业协作、公共测试、上游回馈和国际社区关系。

对中国 AI 开源产业而言，技术突破仍是基础。但当模型、芯片和机器人走向全球，开发者是否容易理解、是否愿意参与、是否相信自己的贡献能够被公平对待，同样会影响技术能否进入更广泛的产品和标准。文化与叙事不能替代产品，却可以把产品所代表的选择讲清楚，并帮助项目找到长期同行者。

## 七、热潮没有回答的四个问题

Omarchy 展示了方向，还没有证明终局。

第一是**安全**。一个能够读取文件、运行命令和修改系统的 Agent，同时也是高权限攻击面。模型不能被当作可信内核。权限隔离、最小授权、操作预览、审计日志、快照回滚和供应链验证，都必须由确定性的系统机制执行，而不能只靠模型“谨慎一点”。

第二是**可复现性**。如果每个人都让 Agent 持续修改机器，系统很快会产生难以解释的配置漂移。真正的可塑机器不仅要容易改变，还要能回答：改了什么、为什么改、怎样在另一台机器重现、怎样安全撤销。

第三是**治理**。项目目前仍高度受益于创始人的声望、表达和判断。随着资金规模和社区影响扩大，基金会能否持续完善资金披露、技术决策、利益冲突管理和社区问责机制，将决定项目能否从依赖个人号召力的快速成长阶段，走向更稳定的公共工程。

第四是**兼容与公共性**。有主见的系统能够减少选择，却也可能把一人的工作方式固化成所有人的默认。它必须允许不同需要的人真正改写，而不是让用户用越来越多反向配置去抵消上游意见。快速成长的社区还需要为技术批评和不同使用方式保留空间。

这些问题并不削弱“可塑机器”的价值。恰恰相反，它们决定这个理想能否从极客兴奋走向可信产品。

## 八、对开源产业真正有用的启示

如果只学习 Omarchy 的视觉风格、宣言句式或创始人传播，很容易停留在视觉与传播层面的模仿。更值得借鉴的是它把几个过去分离的环节重新接在了一起。

**把开放权利做成可用能力。** 不只发布源代码，还要让配置可读、接口可组合、修改可验证、失败可回退，使普通使用者能在 Agent 帮助下真正参与改造。

**把技术主张做成完整产品。** 开放不是把选择题丢给用户。好的开源产品需要默认方案、设计一致性、文档、安装、升级和支持，让人先获得价值，再逐步获得控制。

**把社区热情变成长期供给。** 资金应流向安全、兼容、基础设施、文档、艺术设计和上游维护；对外披露时宜区分现金捐赠、多年期承诺与 Token 额度，避免把不同性质的资源混在一起。

**把个人判断沉淀为公共规则。** 强有力的创始人可以让项目快速出发，但生态要走远，需要可解释的技术路线、贡献边界、决策机制和继任安排。

**把 Agent 当作系统参与者，而不是装饰功能。** 真正的 Agent 原生系统，要从权限、日志、状态、回滚、身份和跨模型迁移开始设计，而不是只在桌面上增加一个聊天入口。

## 结语：所有权是一组可以被验证的能力

“拥有计算机”很容易被说成一种怀旧：重新打开机箱、重新敲击命令、重新回到个人电脑刚出现的年代。

但 Omarchy 所触发的讨论不是回到过去，而是在问一个面向未来的问题：当智能开始代替人操作机器，究竟谁拥有最终决定权？

真正的所有权，不只是购买凭证，也不是一句立场。它至少应当包括几种可以验证的能力：选择模型，检查文件，理解变化，限制权限，撤销操作，迁移数据，更换服务商，并在必要时让系统继续运行。

开放许可证和开放架构，为其中一部分能力提供了法律与工程基础。Agent 则可能让更多人实际使用它们。

这也是《The Malleable Machine》最有力量的地方。它没有证明 Omarchy 一定会赢，却提醒我们，Agent 时代的计算机不应只是更会替用户做事，也应该更容易被用户理解、塑造和带走。

如果这场运动能够把热情变成产品，把个人主见变成公共能力，把快速修改变成安全、可追踪和可回退的工程体系，那么 Omarchy 的意义就不会止于一个 Linux 发行版。

它可能成为一次重新定义“个人计算”的实验。
